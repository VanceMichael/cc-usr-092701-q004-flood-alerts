# 山洪预警闭环处置

围绕山区防汛值班室真实业务实现的预警闭环处置领域服务：把**预警发布、升级、确认、转移、解除、复盘**串成一条可追溯、可恢复的处置链。数据均为演示用虚构内容。

## 参与方

防汛指挥员、水文站人员、乡镇网格员、上级值班人员（县/市/省三级值班）

## 事实资料

- 水利部与中国气象局联合发布黄色山洪灾害气象预警
- 预警涉及湖北西北部、四川东北部、重庆北部和陕西南部等地
- 部门要求实时监测、防汛预警和转移避险

## 闭环规则

| 规则 | 实现 |
| --- | --- |
| 预警锁定 | 每条预警发布时锁定**适用时段、行政区、触发依据**（观测值快照），事后不可变 |
| 迟到观测 | 预警发出后补充到达的雨量/水位只生成**修订建议**，供指挥员决定是否升级，不抹掉已发通知 |
| 蓝→黄并存 | 同一区域先后出现不同级别风险时，前序预警过期留痕，新级别另发新预警；升级则保留完整历史并要求重新确认 |
| 管辖权 | 乡镇只能处理本辖区；县、市、省可处理下级辖区；**跨区联动只能由省级发起** |
| 联动去重 | 相邻区域转移任务经省级挂接后合并台账，按人员唯一编号去重，重复上报不重复计数 |
| 确认升级 | 值守人员 30 分钟内未确认，逐级交接给县、市、省值班，升级只推进到预警失效时点 |
| 解除回避 | **发布人不能批准自己的解除**，须由有管辖权的他人批准；驳回则预警保持生效 |
| 通知失败 | 短信/电话发送失败只生成待办、可重试，**不改变风险状态**，重复失败不重复建待办 |
| 定时推进 | 模拟时钟下按原定时点处理：预警过期、转移逾期（120 分钟）、复盘逾期（24 小时） |
| 重启恢复 | 状态原子写入 JSON，重启后恢复时钟与全部记录，可输出决策追溯链与未闭环人员/区域 |

## 代码结构

```
src/flood_alerts/
  clock.py    只进不退的模拟时钟（含推进历史）
  errors.py   领域错误（管辖权/状态/职责分离/校验/未找到）
  store.py    JSON 原子落盘
  service.py  FloodAlertService：全部处置命令与查询
  demo.py     端到端演练（含服务重启恢复）
contracts/
  context.schema.json  领域资料结构契约
  state.schema.json    持久化状态结构契约
```

## 测试

```bash
python3 -m unittest discover -s tests -v
```

覆盖：预警锁定、迟到观测、升级留痕、辖区越权、联动转移去重、未确认逐级升级、解除职责分离、通知失败待办、定时逾期、重启恢复与未闭环清单。

## 编译

```bash
python3 -m compileall -q src tests
```

## 命令行

领域资料摘要：

```bash
python3 -m src.flood_alerts.context fixtures/context.json
```

端到端演练（可传入状态文件路径，观察重启恢复）：

```bash
python3 -m src.flood_alerts.demo /tmp/flood_state.json
```
