# 山洪预警闭环处置

把山洪预警的**发布、升级、确认、转移、解除、复盘**串成一套可追溯的处置
服务。服务只依赖 Python 标准库（>=3.11），数据均为演示用虚构内容。

## 核心约定

- **证据锁定**：发布/升级时把适用时段（`valid_from`–`valid_until`）、行政区、
  触发依据（观测快照）复制进事件；之后迟到的观测只能形成“修订建议”，
  绝不抹掉或改写已经发出的通知，升级必须经人工确认后另行落事件。
- **权限分层**：乡镇值守人员只能处置本辖区；县级可处置本县；只有**省级**
  能发起跨区域联动转移；预警**发布人不能批准自己的解除**（申请—批准分离）。
- **联动去重**：同一人员在同一预警下只允许一条未完成转移，相邻区域联动
  转移不会重复计数。
- **确认超时上交**：值守人员未在时限内确认，按升级策略沿目录树逐级交接
  （乡镇→县→省），每次交接都落事件并续排确认时限。
- **通知失败不改变风险**：短信/电话发送失败只生成待办（可重试、记录尝试
  次数），预警等级与状态保持不变。
- **人员未闭环不能解除**：仍有未完成（含逾期）转移时拒绝解除申请。
- **模拟时钟**：过期、转移逾期（6h）、复盘（解除/过期后 24h）均为定时器，
  按**原定时点**推进；重启后重放事件日志、恢复时钟并按事件时点重新排定，
  定时器不丢、不重。

## 事件溯源与恢复

- `events.log`：JSONL **只追加**日志，是唯一事实来源；
- `meta.json`：保存模拟时钟当前时刻，临时文件 + 原子替换；
- 重启时重放全部事件重建状态，再重排定时器。`decision_trail()` 回答
  “谁在何时依据哪份观测作出决定”，`open_loops()` 给出尚未闭环的人员、
  区域、复盘、修订建议与通知待办。

## 模块

| 文件 | 职责 |
| --- | --- |
| `clock.py` | 可暂停/快进的模拟时钟与一次性、可取消的定时器 |
| `catalog.py` | 省—县—乡行政区树、值守人员、辖区与跨区权限 |
| `observations.py` | 雨量/水位观测、观测时间与入库时间、风险阈值 |
| `events.py` | 领域事件类型 |
| `store.py` | JSONL 追加存储与原子元数据 |
| `notifications.py` | 可脚本化失败的短信/电话网关 |
| `service.py` | 闭环处置命令、状态机、定时器重放与闭环查询 |
| `demo.py` | 黄色预警全生命周期 + 重启恢复端到端演示 |

## 运行

```bash
# 端到端演示（发布→升级→确认→联动转移→迟到修订→解除→重启→复盘）
python3 -m src.flood_alerts.demo

# 测试
python3 -m unittest discover -s tests -v

# 编译检查
python3 -m compileall -q src tests

# 领域资料摘要（原有）
python3 -m src.flood_alerts.context fixtures/context.json
```
